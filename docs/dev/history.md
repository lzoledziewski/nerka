- **Bookmarks anchored by content, not row number — built (2026-11-01, the owner took the recommendations).** A source gives each line an `Anchor` (`LogSource::anchor`: the byte offset the line starts at in its file, none if its bytes aren't contiguous there, e.g. a reassembled datagram or a syslog copy; and an FNV-1a hash of its first 64 bytes) and finds lines by offset in one pass (`lines_at`). The sidecar gets a 4th column `@<offset>:<hash>` (`@-:<hash>` without an offset); older sidecars load as they are (rows), and older nerka versions would show the column as part of the name (0.x: formats can change). Loading (`Bookmarks::resolve`) puts each bookmark on the line at its offset if the hash matches, else on the nearest line with that hash within 5,000 rows of its old one; one that isn't found **stays on its old row, unsure** (owner: not dropped, no "lost" list): `?` after its name in the Bookmarks panel (hover explains), the views' notes and hover, and the CLI's `marks`; it keeps the anchor it was saved with until its name or note is edited (then it is sure on that line). Content hash only, no file size or time (owner). A view of several files resolves each file against its own source.
- **A core session.** What runs again when the bookmarks, signals or filter change lives in `ui/src/main.rs` (5,300 lines; `Tab` 46 fields): move it into a core `Session` / view model with one `QueryContext` (schema, signals, bookmarks) instead of a `with_*` pass per feature, so the CLI and plugins share it.

- **Protocols as decoders — built (2026-11-01, owner: "DLT just another protocol", proved with real ones: SOME/IP and syslog both; one table with shared columns for mixed captures).** `core/src/input/proto/`: a `Protocol` trait (`split` a datagram into messages, `render` / `detail` the columns after `time`, `field`, `level`, `argument`; `delimited` says whether a message carries its own length) and one source for every container, `Records` (an index of `Framed` entries, 16 B: offset, side-buffer bit, 11-bit channel, 4-bit protocol, time; a `.dlt` file keeps its 8 B offsets and reads time and ECU from each storage header). `DltFile` is `Records` (type alias). The capture router maps UDP destination ports to protocols (`CaptureOptions`: `dlt_udp_ports` 3490, `someip_udp_ports` 30490, `syslog_udp_ports` 514; CLI `--someip-port`, `--syslog-port`; GUI ⚙ → Captures: UDP ports; a port listed twice goes to the first). One protocol in a source: its own columns and fields plus `proto`. Several: columns `time`, `proto`, `info` (the protocol's columns before its payload, in one cell), `payload`, and every protocol's fields (a field of the same name and kind is one field: `payload`; a name two protocols give different kinds is a field of each, `dlt.type` and `sens.type`, in a capture and in a view of several files alike, and a plain `type` there says which to write: review 2026-11-09 R9, `input/schema.rs`); a message's missing fields only satisfy `!=` / `!~`. `proto` is a name field (`FieldKind::Name`): `==` / `!=` ignore case, so `proto == syslog`, `SYSLOG` and `Syslog` are the same (owner, 2026-11-01). **SOME/IP** (`proto/someip.rs`): headers only (service, method, client, session, iface, type, rc, len; payload as hex; `SD` marked; level Error for ERROR types or a return code other than E_OK, else Info); no TCP, no SOME/IP-TP reassembly, payloads not decoded (FIBEX / ARXML later). **Syslog** (`proto/syslog.rs`): RFC 5424 and RFC 3164 over UDP (facility, severity as the level, host, app, pid, msgid, the message's own stamp); not delimited, so the capture keeps each message behind its length in the side buffer.
