## Summary

The definition reader is robust. 28,000 mutated definitions (sizes, counts, enum values and kinds changed, numbers up to and past `i64::MAX`; past it a definition is refused when it loads) read well-formed DLT messages of every kind without a panic, in release and in debug (overflow checks on). Type and instance chains as deep as the limits allow fit the 1 MiB stack of a Windows main thread. Definitions are bounded where it matters: 1 MiB of YAML, 1024 nodes, 64-deep expressions, 65,536 list items, 200 levels of nesting at run time. DLT as a definition gives the same match counts as native DLT in every benchmark query. The native readers' numbers are unchanged, though every captured datagram now goes through the rule router.

What needs attention:
- **The review gate lied:** its benchmark didn't run, and it said PASS (fixed here).
- **Routing surprises:** a user's rule can lose, silently, to another protocol's default rule.
- **Smaller usability gaps** in the CLI's new error paths.
- **Old debt that keeps growing:** `status.md` and `ui/src/main.rs`.
